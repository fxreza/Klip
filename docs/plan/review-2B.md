# Task 2B — Refute-review of the rebuilt UI vs. the preservation checklist

Reviewer stance: default to REGRESSED unless a code path or a real test/harness run proves otherwise. Covers PLAN.md §7 (12-item checklist), §6 traceability, and buffer.md §3 feature inventory, against the code as merged through 3D/3E/3F/3G/3H (4A iCloud sync excluded — out of scope, in progress).

## Method
- Build: `scripts/build_local.sh` — clean, 14 warnings (matches documented baseline, no new warnings).
- Unit tests: `scripts/run_tests.sh` — **183/183 passed** (FileClipTests, RichCaptureTests, FolderTests, FolderUXTests, LockTests, ShortcutTests, KeyMonitorTests, ContentDetectorTests, FilterStateTests, PermissionsTests, SettingsManagerTests, ClipboardStoreTests, ClipboardItemTests).
- Behavior harness: adapted 2A's `BehaviorHarness.swift` (offscreen, drives `HistoryViewModel` against a real `ClipboardStore`) to the 2B worktree and current API (`PasteMode` param added to paste/copy closures by 3D) — **70/70 checks passed** after the adaptation, covering scope/chip/tag/search combine, multi-select, edit mode, Esc chain, folder create/scope-fallback, reopen persistence (90s), sidebar/preview toggles, lock-blocks-delete, and chunked large text.
- Code trace for UI-only paths that need a real mouse (window chrome, drag-and-drop, status bar clicks) — screen is locked, so no `screencapture`; traced against the actual source instead.
- Migration test: copied the **real** `~/Library/Application Support/Buffer/history.json` (32 items, untouched — verified same md5 before/after) into an isolated `KLIP_DATA_DIR`, ran the built `Klip.app` against it, confirmed it loads and re-saves.
- Four areas (Folders, Custom Shortcuts, File clips, Rich text) were independently code-traced by parallel review agents with the same refute stance; their file:line citations are folded into the table below.
