## Required behavior
1. **Capture keeps the original encoding.** When the pasteboard has image data, pick the first available in this order and store its bytes **verbatim**: `public.jpeg` -> `.jpg`, `public.png` -> `.png`, `public.heic` -> `.heic`, `com.compuserve.gif` -> `.gif`, `public.webp` (if present) -> `.webp`; only when none of those exist (e.g. TIFF-only, or a vector/PDF image type) fall back to today's NSImage -> PNG conversion. A single image *file* copied in Finder keeps its bytes and extension the same way (read the file data, do not re-encode). Never re-encode JPEG/PNG/HEIC/GIF/WebP. Keep the 4096 px cap behavior only for the fallback path (document that large JPEG/PNG are stored as-is).
2. **Model/storage**: `imageFilename` may now end in any of those extensions; everything that assumed `.png` must use the stored filename (`image(for:)`, thumbnails, OCR, delete, `itemSize`, sync asset copy, orphan sweep, migration of old `.png` entries untouched). Add `var imageUTI: String?` to `ClipboardItem` (Codable, optional; derive from the extension when nil for old items).
3. **Paste/copy restores the same format**: write the stored bytes to the pasteboard under their UTI (`NSPasteboard.PasteboardType(rawValue: uti)`) as the first type; for JPEG/HEIC/GIF/WebP additionally offer a **TIFF** representation decoded from the same bytes as a second type so apps that only accept PNG/TIFF still paste (this does not alter the primary bytes; apps that understand the primary type get the original file). For PNG the primary type is `.png` plus TIFF as today's fallback. Multi-paste temp files use the original extension (`image-0001.jpg`). Dedupe hash = hash of the stored bytes.
4. **Save to Disk** and **Save All** default to the original extension and write the original bytes (no conversion); the preview header's byte size shows the stored size.
5. **Sync**: asset mirroring, dedupe and `imageHash` logic use the actual filename/bytes; a JPEG captured on one Mac arrives as the same JPEG on the other.
6. Settings: nothing new. CHANGELOG `## 3.0.3` entry; `Info.plist` 3.0.3 / build 11.
7. Tests: watcher test with a private `NSPasteboard` holding JPEG bytes (make a JPEG with `NSBitmapImageRep.representation(using: .jpeg, properties: [.compressionFactor: 0.7])`) -> stored file is byte-identical, extension `.jpg`, `imageUTI == "public.jpeg"`; PNG stays PNG; TIFF-only falls back to PNG; Finder-copied `.jpg` file stays byte-identical; paste writes `public.jpeg` as first type with identical bytes; save-to-disk name/bytes; old items with `.png` filename and nil `imageUTI` still load/render/paste.
