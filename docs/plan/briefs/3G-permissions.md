## Deliverables
1. `Services/PermissionsState.swift` - `@MainActor final class PermissionsState: ObservableObject` singleton: `@Published accessibilityTrusted` (`AXIsProcessTrusted()`), `startPolling()/stopPolling()` (1 s timer, only while a permissions/onboarding window is visible - not forever), `onBecameTrusted` fired once on the false->true edge, `requestAccessibility()` = `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt: true])` + open `x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`, `openAccessibilitySettings()`, `launchAtLoginEnabled` (via `SettingsManager`/`SMAppService`), `iCloudDriveAvailable` (`~/Library/Mobile Documents/com~apple~CloudDocs` exists; used by Phase 4).
2. `Views/Permissions/PermissionsView.swift` - rows with status pill (green "Granted" / orange "Needed" / grey "Not available"): **Accessibility** (why: "needed to paste into the app you were using; without it Klip still copies to the clipboard and you press ⌘V yourself"; buttons Grant… / Open System Settings…), **Launch at Login** (toggle bound to settings), **iCloud Drive** (for Sync; "Sign in to iCloud and turn on iCloud Drive" when missing), and a note that Klip needs no other permissions (no screen recording, no network beyond update checks). Use `Theme`/`Font.klip`. `PermissionsWindowController` (like the settings window in `StatusBarController.showSettings`) to present it at ~480x420.
3. `Views/Permissions/OnboardingView.swift` - first-run window (440 wide): icon with `Theme.accentGradient`, "Welcome to Klip", the Accessibility status card, primary button ("Grant Accessibility Access" when needed, "Get Started" when granted), "Skip for now". Sets `SettingsManager.hasCompletedOnboarding` (new key `onboarding.completed`, default false). When `onBecameTrusted` fires while visible: close and show the history window 0.3 s later.
4. `AppDelegate.swift`: replace the unconditional `AXIsProcessTrustedWithOptions` prompt with: `if !trusted && !hasCompletedOnboarding { show onboarding after 0.4 s }`; if onboarding was completed, never prompt automatically (user reaches Permissions… from the menu). Keep the `KLIP_DEBUG` skip (no windows, no prompts).
5. `Views/StatusBarController.swift`: menu item **Permissions…** below Settings…, opening the permissions window.
6. `Views/SettingsView.swift`: add a **Permissions** tab that embeds `PermissionsView` (same view, no window chrome).
7. `Services/PasteController.swift`: before simulating ⌘V, if `!AXIsProcessTrusted()` post `Notification.Name.klipPasteNeedsAccessibility` (declare it in `Services/PermissionsState.swift`) and still put the content on the pasteboard (today's behavior). `AppDelegate` observes it and shows `Views/Permissions/AccessibilityToast.swift`: a small non-activating HUD panel (style like `UpdateService`'s toast: material, rounded, auto-dismiss 6 s) saying "Copied. To paste automatically, give Klip Accessibility access." with an "Open Permissions…" button. Rate-limit to once per 60 s.
